Extended State Machine Types

Five specialized state machine implementations with bidirectional mapping between design diagrams and C code, supporting entry/do/exit actions and priority‑based configuration.

🖥️ 1. Mealy UI State Machine

Scenario: UI Interface Control

Type: Mealy event‑driven

Key Features: Output depends on event and state, entry/do/exit actions per state, visual feedback mapping.

  • States: Idle, Hovered, Pressed (with sub‑states)
  • Events: hover, click, keypress
  • API: mealy_machine_dispatch_event()
  • Code: mealy_ui.c / mealy_ui.h

📡 2. EFSM Protocol State Machine

Scenario: Communication Protocol

Type: EFSM + Three‑Stage

Key Features: Extended variables (sequence_number, timeout_counter), guarded transitions, three‑stage processing.

  • States: Idle, Receiving, Processing, Sending, WaitingAck
  • Events: packet_arrival, packet_complete, valid, invalid, sent, ack_received, timeout
  • API: efsm_protocol_process()
  • Code: efsm_protocol.c / efsm_protocol.h

⚙️ 3. Moore Hierarchical State Machine

Scenario: Embedded Control

Type: Moore + Hierarchical

Key Features: Output depends only on state, hierarchical nesting, entry/do/exit actions per state, temperature‑based transitions.

  • States: Off, On (with substates Heating, Cooling, Idle, FanOnly)
  • Events: power_on, power_off, temp_high, temp_low, temp_ok, fan_on, fan_off
  • API: moore_hsm_dispatch_event(), moore_hsm_set_temperature()
  • Code: moore_hierarchical.c / moore_hierarchical.h (complex thermostat example)

🔀 4. Parallel State Machine

Scenario: Concurrent System

Type: Parallel FSM

Key Features: Multiple independent FSMs, broadcast synchronization, entry/do/exit actions per component.

  • Components: A, B, C (each with Idle, Active, Done)
  • Events: start, data_ready, finish, enable
  • API: parallel_machine_broadcast_event()
  • Code: parallel_fsm.c / parallel_fsm.h

🔤 5. Acceptor FSM (Regex)

Scenario: Regular Expression Matching

Type: Acceptor (Receiver) FSM

Key Features: Accepts/rejects input strings, character‑based transitions, entry/do/exit actions per state.

  • States: q0 (initial), q1 (accepting), reject
  • Events: characters 'a', 'b'
  • API: acceptor_machine_feed()
  • Code: acceptor_regex.c / acceptor_regex.h
