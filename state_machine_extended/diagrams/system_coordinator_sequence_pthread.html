Description

This sequence diagram illustrates four main scenarios with explicit thread boundaries:

  1. Normal Recording Flow: User starts recording, system transitions through IDLE → RECORDING → UPLOADING → IDLE states. The flow crosses from main thread to recording thread and then to communication thread.
  2. Error Recovery Flow: Error occurs during recording, system enters ERROR state, then resets to IDLE. Error handling involves coordination between recording thread and main thread.
  3. Power Management Flow: Low battery warning triggers SLEEP state, then power off leads to SHUTDOWN. Power events originate from power thread and propagate to other threads.
  4. External Device Control Command Flow: External device sends commands via Bluetooth/4G, which are processed by an external command processor (external thread) and dispatched to the system coordinator (main thread).

The diagram shows interactions between:

  • User: Initiates actions via test program (runs in main thread).
  • Test Program: Calls system coordinator API functions (main thread).
  • System Coordinator: Main coordinator FSM (main thread).
  • Recording FSM: Handles audio recording operations (recording thread).
  • Power FSM: Manages power states (power thread).
  • Comm FSM: Handles communication and upload (communication thread).
  • External Device: Sends control commands via wireless (external thread).
  • External Command Processor: Parses and forwards commands to system coordinator (external thread).

Thread‑Safety Note: Cross‑thread communication is implemented using thread‑safe queues and event posting mechanisms. The diagram uses dashed boxes to visualize which participants belong to the same pthread, helping to identify potential concurrency issues.
