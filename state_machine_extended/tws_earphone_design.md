# TWS耳机系统状态机设计文档

## 产品概述
- **产品名称**：智能录音TWS耳机系统
- **组件**：
  1. TWS耳机（左右耳）
  2. 充电盒（带4G modem）
- **核心功能**：
  - 传统TWS耳机功能（音频播放、通话）
  - 录音功能（耳机：MIC+speaker混音；充电盒：MIC）
  - 录音文件实时上传（通过4G网络）
  - 控制指令下发（通过4G网络）
  - 蓝牙通信（耳机↔充电盒）

## 状态机架构设计

### 1. 系统级状态机组合

```
┌─────────────────────────────────────────────────────────┐
│                   顶层协调状态机                         │
│  (SystemCoordinatorFSM)                                 │
├─────────────────────────────────────────────────────────┤
│ 状态：INIT, IDLE, RECORDING, UPLOADING, ERROR, SLEEP    │
└────────────────┬────────────────────────────────────────┘
                 │ 协调所有子系统
                 ▼
┌─────────────────────────────────────────────────────────┐
│                并行子系统状态机                          │
├──────────────┬──────────────┬──────────────┬────────────┤
│ 录音控制     │ 通信控制     │ 电源管理     │ 音频处理   │
│ RecordingFSM │ CommFSM      │ PowerFSM     │ AudioFSM   │
└──────────────┴──────────────┴──────────────┴────────────┘
```

### 2. 各子系统详细设计

#### 2.1 录音控制状态机 (RecordingFSM)
**职责**：管理录音的开始/停止，协调耳机和充电盒的录音源

**状态**：
- `REC_IDLE`：空闲状态
- `REC_WAIT_SYNC`：等待耳机和充电盒同步
- `REC_RECORDING`：正在录音
- `REC_PAUSED`：录音暂停
- `REC_STOPPING`：停止录音中
- `REC_ERROR`：错误状态

**事件**：
- `EVT_REC_START`：开始录音（来自耳机或充电盒按键）
- `EVT_REC_STOP`：停止录音
- `EVT_REC_PAUSE`：暂停录音
- `EVT_REC_RESUME`：恢复录音
- `EVT_REC_SYNC_COMPLETE`：设备同步完成
- `EVT_REC_ERROR`：录音错误

#### 2.2 通信控制状态机 (CommFSM)
**职责**：管理蓝牙和4G通信

**子状态机**：
- **蓝牙通信状态机 (BluetoothFSM)**
  状态：`BT_DISCONNECTED`, `BT_CONNECTING`, `BT_CONNECTED`, `BT_TRANSFERRING`
- **4G网络状态机 (NetworkFSM)**
  状态：`NET_OFFLINE`, `NET_CONNECTING`, `NET_ONLINE`, `NET_UPLOADING`

#### 2.3 电源管理状态机 (PowerFSM)
**职责**：管理电源状态，优化能耗

**状态**：
- `PWR_OFF`：关机
- `PWR_ON`：开机
- `PWR_LOW_BATTERY`：低电量
- `PWR_CHARGING`：充电中
- `PWR_SLEEP`：睡眠模式

#### 2.4 音频处理状态机 (AudioFSM)
**职责**：管理音频流的处理

**状态**：
- `AUDIO_IDLE`：空闲
- `AUDIO_PROCESSING`：处理音频
- `AUDIO_BUFFERING`：缓冲中
- `AUDIO_MIXING`：混音处理（耳机端）
- `AUDIO_ENCODING`：编码处理

## 状态机通信机制

### 1. 事件广播机制
- 顶层状态机可以广播事件到所有子系统
- 子系统之间可以通过事件进行通信

### 2. 消息队列
- 使用消息队列进行异步通信
- 支持优先级消息处理

### 3. 共享数据区
- 录音状态共享（当前录音文件信息）
- 网络状态共享（连接质量、信号强度）
- 电源状态共享（电量百分比）

## 关键业务流程

### 1. 开始录音流程
```
1. 用户按下耳机或充电盒的录音按键
2. RecordingFSM接收EVT_REC_START事件
3. RecordingFSM进入REC_WAIT_SYNC状态
4. 通过BluetoothFSM同步耳机和充电盒
5. 同步完成后，RecordingFSM进入REC_RECORDING状态
6. AudioFSM开始处理音频流
7. 录音数据通过BluetoothFSM传输到充电盒
```

### 2. 停止录音并上传流程
```
1. 用户再次按下录音按键
2. RecordingFSM接收EVT_REC_STOP事件
3. RecordingFSM进入REC_STOPPING状态
4. AudioFSM停止处理音频
5. RecordingFSM生成录音文件
6. NetworkFSM连接到4G网络
7. 录音文件通过NetworkFSM上传到云端
8. RecordingFSM返回REC_IDLE状态
```

### 3. 外部设备控制指令流程
```
1. 外部设备（如手机App或云端服务器）通过蓝牙或4G发送控制指令
2. CommFSM接收数据，触发COMM_EVT_DATA_RECEIVED事件
3. 外部命令处理器（ExternalCommandProcessor）解析原始数据
4. 根据配置模式处理指令：
   - 直接事件模式：立即向SystemCoordinator分发对应事件
   - 回调队列模式：将指令加入优先级队列，周期性处理
   - 混合模式：高优先级指令立即回调，低优先级入队列
5. SystemCoordinator根据事件类型执行状态转换
6. 执行结果通过CommFSM返回给外部设备
```

## 非功能性需求考虑

### 1. 实时性要求
- 按键响应：< 50ms
- 音频处理延迟：< 20ms
- 蓝牙传输延迟：< 100ms

### 2. 内存限制
- 嵌入式环境，内存有限
- 状态机设计需考虑内存占用
- 使用静态内存分配

### 3. 功耗优化
- 状态机设计需考虑功耗
- 空闲时进入低功耗状态
- 按需激活子系统
