🏗️ System Coordinator FSM

Scenario: TWS Earphone System Coordination

Type: Moore Hierarchical + Coordinator Pattern

Key Features: Coordinates multiple subsystem FSMs, manages system‑wide state transitions, error recovery, power management.

  • States: INIT, IDLE, RECORDING, UPLOADING, ERROR, SLEEP, SHUTDOWN
  • Events: 16 system events (POWER_ON, REC_START, ERROR, RESET, etc.)
  • API: system_coordinator_dispatch_event()
  • Code: system_coordinator.c / system_coordinator.h
  • Subsystems: Recording FSM, Communication FSM, Power FSM, Audio FSM

🔗 Subsystem Coordination

Architecture: Hierarchical coordination of specialized FSMs

Coordination Pattern: Master‑slave with event broadcasting

Key Features: Loose coupling between subsystems, centralized error handling, state synchronization.

  • Recording FSM: Manages audio recording states (IDLE, RECORDING, PAUSED, STOPPED)
  • Communication FSM: Handles Bluetooth/Wi‑Fi connectivity and data transfer
  • Power FSM: Manages battery states, charging, low‑power modes
  • Audio FSM: Controls audio playback, volume, equalizer settings
  • Error Propagation: Subsystem errors bubble up to system coordinator

🎤 Recording FSM

Purpose: Manages audio recording lifecycle for TWS earphones

Type: Mealy Event-Driven State Machine

Key Features: Recording control, pause/resume, audio buffer management, quality settings

  • States: IDLE, RECORDING, PAUSED, STOPPED, ERROR
  • Events: REC_START, REC_PAUSE, REC_RESUME, REC_STOP, ERROR
  • API: recording_fsm_handle_event()
  • Code: recording_fsm.c / recording_fsm.h
